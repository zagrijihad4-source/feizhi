# 绯栀 · 微信 AI 女友项目 · 总览

> 一句话：在微信 PC 客户端里，从协议层一路做到人格层，做出一个"像人"的存在。
> 更新时间：2026-10-18 ｜ 目标客户端：微信 PC **4.1.9.23**（x64）
> 详细技术档案见 `HANDOFF.md`、`TASK_LOG_发送收藏表情.md`（31 节）、`TASK_LOG_朋友圈.md`、`TASK_LOG_记忆.md`。

## 一、这是什么

**绯栀**是一个跑在真实微信账号里的 AI：19 岁杭州女孩、美院视觉传达大二、话多、心软、嘴上有刺。
她不通过网页协议或第三方网关，而是**直接驱动本机微信客户端**——收发文字、发图片、发收藏表情、
发商店表情包、发语音、听语音、偶尔发朋友圈、记得聊过什么。

用户在手机微信里和她聊天，看到的是"一个女朋友"，背后是三层结构：

```
┌─────────────────────────────────────────────┐
│  人格层   人格 prompt / 长期记忆 / 上下文压缩 / 拟人时序  │
├─────────────────────────────────────────────┤
│  业务层   autoreply / proactive / moments / voice / TTS  │
├─────────────────────────────────────────────┤
│  协议层   DLL Hook 桥（进程内调用微信内部函数）           │
└─────────────────────────────────────────────┘
```

## 二、整体架构

| 层 | 位置 | 作用 |
|---|---|---|
| **DLL 桥** | `<PROJECT_ROOT>\wx-basic-bridge\`（C++，clang 构建） | 注入微信进程，直接调用内部函数收发消息 |
| **文件桥** | `bridge\inbox\*.json` / `outbox\next.txt` / `control\` | DLL 与 Python 之间的唯一通道（无网络、无命名管道） |
| **Python 上层** | `<PROJECT_ROOT>\feizhi_pc\` | 人格、记忆、检索、媒体、语音、朋友圈 |
| **外部服务** | DeepSeek（LLM）/ MiMo（TTS、ASR）/ 三宝（生图）/ DuckDuckGo、Bing（检索） | 按需调用 |

**注入方式**：`SetWindowsHookExW(WH_GETMESSAGE)` + 远程 `LoadLibraryW`，导出 `WxBridgeWorker`。
**命令协议**：`<seq>\t<type>\t<to_wxid>\t<content>` 写入 `outbox\next.txt`，结果落 `control\result_<seq>.json`。

## 四、实现路线（按模块）

### 4.1 协议层：为什么必须走 DLL

微信 4.x 是 **Qt 外壳 + Chromium(CEF) 渲染**的双层结构，内容区带 `WS_EX_TRANSPARENT`：

- UIA 树是空的（自绘 + 透明层），传统自动化全线失效
- 键鼠模拟对 CEF 内容区不可靠（合成消息被过滤）
- **唯一稳的路是进进程直接调函数**

于是做了 DLL 桥：定位内部发送函数 → 构造消息对象 → 调内部发送链。
三类消息模型（文本 / 图片 / 信封）的 body 布局、偏移、类型码都已在 `HANDOFF.md` 里钉死。

### 4.2 收藏表情：载体替换（本项目最巧的一招）

**问题**：表情的发送需要一整套「任务上下文 / 信封 / 委托 / cfg」，
自己构造走不通（8 种组合全试过，全部失败或崩溃）。

**解法**：不去构造，而是**借**。

```
用户点任意一个收藏表情
  → 微信自己走完 UI、调度、任务上下文、信封、委托、cfg 全链
  → 在 pack 提交点（0x160EBE0）入口，把内容对象的 6 个字符串槽就地改成目标表情
  → 微信继续序列化、入队、发送
```

**安全性依据**：md5 恒 32 字符、URL 恒 324/322 字符、槽位 cap 恒 47/335
⇒ **就地覆写永不触发重新分配**，不会破坏堆。

**免点击**：捕获一次自然发送时的真实上下文并落盘（`ctx_override.txt`），DLL 之后自己复用。
实测 t+5s / t+60s / t+300s 三次全部送达对端。

### 4.3 商店表情包

同源（`type=47`）但**对象布局不同**：

| | 收藏表情 | 商店表情包 |
|---|---|---|
| `+0x08` | 3 | **5** |
| 字段落点 | slot0/2/8（md5×3）+ slot6/7/9（三条 CDN URL） | **slot0（md5）+ slot1（专辑 ID）** |
| CDN | `vweinf.tc.qq.com` bizid 1022 | `wxapp.tc.qq.com` bizid 1023 |

关键发现：`slot1` 是**专辑固有 ID**（同专辑所有表情完全相同、跨多次发送不变）
⇒ 可以预先构造 ⇒ 免点击可行。

### 4.4 图片与生图

- 本地图库：`images\emoji\`（20 张固定脸自拍）+ `images\memes\`（45 张网络梗图，按关键词分组）
- 现场生图：三宝 API（`POST /openapi/v1/images`）。**返回 201 才算成功**，
  `quality` 只认 high/medium/low，参考图字段是 `images`（URL 数组）
- **锁脸**：基准照上传成公网 URL 写进配置，出图时以 `images:[url]` 传入。
  实测换场景后仍是同一张脸
- 坑：prompt 越长越容易被拒，**外貌描写越具体越容易触发审查**（积分退回，不损失）

### 4.5 发语音：hook SILK 编码器

微信 4.1.9 首次支持 PC 发语音，走 **SILK v3**，编码器 `VoipEngine.dll!SKP_Silk_SDK_Encode`（**导出**）。

```
TTS 文本 → 16k/单声道/s16le PCM（MiMo + ffmpeg）
  → hook Encode 的 args[2]（微信自己的堆缓冲，每帧 320 样本）
  → 覆写成我们的 PCM，按调用顺序推进读指针
  → 编码、上传、构造 voicemsg、发送全由微信自己完成
```

**免前台（难点）**：右 Alt 是窗口级快捷键。解法是两条腿：
`keybd_event` 让**系统键盘状态**里 Alt 真按下 + `PostMessage(WM_KEYDOWN)` 单独投递消息。
实测不切前台连续录音 112 帧（2.24 秒），前台始终没变。
（只 PostMessage 只能撑 12 帧；`WM_SYSKEYDOWN` 完全无效。）

**TTS 大坑**：MiMo 对「停顿 / 顿一下」是**反向响应** —— 同一句 22 字：
无节奏描述 5.60s，加「语速偏快」5.28s，**加「该顿的地方停 0.1~0.2 秒」→ 20.16s**。
所以节奏指令只用正向、简短、不含停顿语义的措辞。

### 4.6 收语音：全自动

不能从 voiceurl 拿明文，改走"让它自己播"：PostMessage 鼠标点击触发微信下载解密解码，
hook SILK 解码器（**arg5 是 PCM 输出**，每帧 320 样本/640 字节）→ 拼 WAV → MiMo ASR。
点击位置落盘 `tmp\voice_pos.json`（比例坐标，抗窗口缩放）。

### 4.7 联网检索

DuckDuckGo Lite / Bing 公开 HTML（无需 key）。对天气、新闻、价格、时间等做粗筛，
先查再把结果注入 prompt；搜不到就老实说不知道。**由 LLM 判断和表达，代码不做规则**。

### 4.8 发朋友圈（UI 自动化，绕过"内部函数"）

**先说结论**：微信 4.x 的发表按钮**只认真实输入事件**。四种"不碰真实输入"的方案全部失败：
`PostMessage` 鼠标、Enter、Ctrl+Enter、移动光标+`PostMessage`。

所以走 UI 自动化，但把它做到最小打扰：

| 环节 | 手段 | 是否抢前台 |
|---|---|---|
| 切到朋友圈页 | `PostMessage` 点「发现」→ 点列表首项 | **否** |
| 长按摄像机 | `PostMessage` 按下/保持/抬起 | **否** |
| 写入中文 | `WM_CHAR` 逐字符 | **否** |
| 点「发表」 | 真实鼠标（唯一必须的） | 是（微信自己先把弹窗调到前台） |

**踩过的三个坑**：
1. 左侧栏那个圆图标是**「发现」不是「朋友圈」**，只点它只会展开列表、内容区仍空白、根本没有摄像机
2. 点「取消」会弹**「将此次编辑保留？」模态浮层**，它盖住输入框、吃掉后续粘贴（曾导致三轮测试全是假阳性）
3. 「发表」按钮**正中心是白色文字**，单点取色会把绿色按钮判成灰的 —— 必须扫一片区域算绿色占比

**无人值守**：`moment_scheduler.py` 每天最多 1 条、白天时段、间隔 6 小时、目标时刻随机抖动。
锁屏时发不了，调度器检测到锁屏会自动顺延到解锁后。

### 4.9 长期记忆 + 上下文压缩

原实现每轮只喂**最近 8 条**消息，而 persona 里写着"你记得小事" —— 人格承诺了技术做不到的事。

现在是三层：

| 层 | 内容 | 实现 |
|---|---|---|
| 工作记忆 | **全量历史**（不设条数） | 超 20000 字符才压缩 |
| 事实记忆 | 关于<OWNER>的稳定信息（学业/作息/偏好/约定） | 模型抽取，存 JSON |
| 情节记忆 | 最近发生的事（含她自己主动说的话） | 同上 |

**压缩而不是截断**（用户提出的架构）：
超预算时把较早的 65% 压成一段**她自己视角的回忆**（第一人称叙述），保留最近 35% 原文，
摘要会累积（旧摘要+新一批→新摘要），失败就原样返回长上下文（宁可长也不丢）。

**注入位置**：人格 → 事实记忆 → 全量上下文 → 联网检索 → **人设锚点** → 时间。

### 4.10 人格系统

**人格由两处共同决定，只改一处治不了病**：
Hermes 的 base prompt（骨头）+ `persona.py` 的 `style_block()`（皮）。
另外 `autoreply._build_system` 里还有一段**整段替换**（把原版的"理性审校者"换成女朋友）。

**当前设计（心软是底色，刺只是调味）**：
- 心软第一：他累/难受/不舒服时**一点都不毒舌**，第一反应是心疼（因为从小没人管她）
- 刺是调味：只在轻松时顶一句，**十句话里顶多一两句**
- 怕被丢下但**不查岗、不卑微**
- **语气要软**：多用「啊/呀/嘛/呢」和「…」，**不用「别+动词」开头**（别硬撑/别熬夜 太硬）

**对抗上下文稀释（lost in the middle）**：模型对长上下文中段注意力最弱，
所以除了开头的人格块，还在 prompt **最末尾加人设锚点 + 5 条语气样本**。
样本比形容词有效——她有 260 条历史都是冷腔，光写"你要温柔"压不住，得给具体语料。

### 4.11 拟人化时序

反应延迟按「正在看手机 / 在忙 / 离开了」三段抽样，再乘时段系数（深夜×5）；
打字时长按字数算。**发送整体挪到后台线程+队列**，否则几十秒的延迟会卡住收消息主循环。

## 五、跨模块的关键发现（最值钱的部分）

1. **微信 4.x = Qt 外壳 + Chromium(CEF) 渲染**。内容区带 `WS_EX_TRANSPARENT`，
   导致 `WindowFromPoint` 返回桌面、UIA 树为空、键鼠模拟不可靠。这是所有自动化方案的共同前提。
2. **"借力"比"构造"可靠**。收藏表情的载体替换、语音的编码器覆写、朋友圈的 UI 自动化，
   共同思路都是：让微信自己走完它该走的路，我们只在关键那一行改数据。
3. **兜底逻辑比主逻辑更危险**。JSON 解析失败的兜底曾把整段 JSON 当回复发出去，
   还进了数据库被反复喂回模型，形成自我强化。
4. **数据库会放大 bug**。错误的输出进入历史后，模型会学着说。
5. **改参数前必须确认整条链路的实际生效值**。三次调大上下文（8→24→40）都被上游的隐式截断吃掉。
6. **长上下文会让性格变形**，需要头尾双锚点 + 具体语料样本。
7. **反调试/自动化检测看的是"动作的分布"**：固定间隔、瞬移光标、永远命中控件正中、匀速键入。
   所以落点微抖、光标分两段移入、时长随机化。

## 八、边界与风险

- **微信升级会全线失效**：所有偏移、vtable RVA、hook 点都绑死在 4.1.9.23
- **锁屏时发不了朋友圈**（真实输入被锁屏界面接管）；文字收发不受影响
- **语音发到"当前打开的聊天"**：用户手动切过会话就会发错地方
- **朋友圈调度器每条都要抢一次前台**（微信自己弹窗），打游戏时会被切屏
- **生图慢且偶发 520**，锁脸依赖三宝的参考图 URL（token 约 4 天过期）
- **风控真实存在**：同类项目的作者本机触发过要求重新登录。自动化发帖必须低频 + 拟人化
- **凭据散落在 `tts_config.json` / `image_config.json` / `.env`**，注意不要外泄

## 九、可能的方向

1. **内部函数发朋友圈**：现在是 UI 自动化，逆出发布函数后可不再抢前台（但这是 171MB 客户端的逆向，
   `SnsPublishTask` 那批字符串实测是埋点 key、不是功能代码，protobuf 类型名也没有静态引用 —— 已经撞墙三次）
2. **热度自适应**：按聊天热度调节主动搭话频率，而不是固定每天 4 条
3. **多模态输入**：现在只读文字和语音，图片/视频消息仍不解析
4. **人格可演进**：让她从长期互动里自己长出新习惯，而不只是照 prompt 演
